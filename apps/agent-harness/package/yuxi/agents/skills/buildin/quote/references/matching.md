# 匹配与时效规则

先读本文件再逐项估时。输出用词以 `output-spec.md` 的模拟金样为准。

## 检索顺序

对 D0 每一行只走一条主路径，允许「部分匹配」把缺口补到下一层，但**各层时效只加不乘**。

```
核心功能描述
    │
    ├─ 能对齐标准最小销售单元，且主路径可直接复用  → P1 已匹配
    ├─ 能对齐标准最小销售单元，但缺接口/场景/规则 → P1 部分匹配 + 缺口走 P2/P3
    ├─ 标准无该单元，历史有相似功能或组合         → P2
    └─ 两库都无                                    → P3 未匹配
```

匹配键是「核心功能描述」中的**角色 + 操作 + 业务对象 + 目标**，不是三级功能标题。标题相同但对象不同（机构 vs CP/SP、AI 平台 vs IPTV 栏目）最多算部分匹配。

## 最小销售单元

标准清单通过两列判断，值为「是」才是可报价单元：

- `二级功能是否为最小销售单元`
- `三级功能是否为最小销售单元`（焊点检测表头写作「三级功能是-为最小销售单元」，按同义列处理）

取值：`是` = 可独立销售；`-` = 附属能力，并入其依赖的最小销售单元，不要单独报价，除非用户把它写成独立需求。

空值、合并单元格向下填充后再判断。`/` 视为无效三级名，回退用二级功能名。

## P1 标准产品

标准产品清单由用户提供文件，或从知识库检索后用 `download_kb_file` 落到沙盒再读。按用户对标产品选 Sheet：

| 用户意图 | Sheet |
| --- | --- |
| IPTV / CMS / EPG / 质量监测 / 会员 / 推荐 | 数智全链运营 |
| 酒店 / 行业 EPG / 客房 / 旅游 | 智慧行业 |
| 焊接 / 焊点 / 返修工单 | 焊点检测 |
| 未指定 | 三张都检索，命中后写清 Sheet |

`智能体中台` Sheet 当前为空，视为无标准产品，不要假装命中。

时效列（仅数智全链运营有表头）：`标准产品时效` / `标准研发时效` / `标准交付时效`。

**时效降级（必须执行）：**

1. 三列都有数 → 原样采用，匹配来源只写标准清单。
2. 功能已命中但时效为空 → **功能匹配结果仍按能力复用程度写**，时效不得留空、不得默填整数：
   - 历史库有同类最小销售单元或等价组合 → 时效改走 P2 中位数；匹配来源写成 `标准化产品功能清单.xlsx（Sheet：…） + {历史文件名}`；依据写「功能对齐标准清单，时效取历史中位数（标准清单时效字段为空）」。
   - 历史也无 → 时效走 P3；匹配来源写成 `标准化产品功能清单.xlsx（Sheet：…）；时效：AI评估（标准清单时效字段为空）`。
3. 禁止用「经验值 1/2/3 人天」填空。

当前权威文件中，三张标准 Sheet 的时效列基本为空。默认走第 2 步，不要假设标准清单已有固定时效。

## P2 历史项目

历史清单由用户提供文件，或从知识库检索。当前已知结构示例：`重数传媒AI监播监控智能体功能清单.xlsx`。列：`一级功能 | 二级功能 | 三级功能 | 功能描述 | 产品 | 研发 | 交付 | 合计`。最后一行是合计（一级功能空、合计约 87），计算时排除。

取数规则：

- 单点相似：取该行 `产品` / `研发` / `交付`。
- 多条都相似：对三列分别取**中位数**，不要取平均数，不要取合计列再反拆。
- 用户一个最小销售单元覆盖历史多条原子任务：取这些行三列分别求和（组合总时效），依据写清「组合含哪些三级功能」。
- 优先全部呈现：对话摘要列出被纳入中位数或组合的历史行，不要只留一个「最像」却丢掉时效依据。

历史行是细粒度原子任务（中位合计 0.7 人天）。报价行若是较粗的最小销售单元，必须先组再加，不要把 0.7 直接当成整模块时效。

若后续追加历史清单，文件名按原名写入「匹配来源」。模拟金样中的 `湖北质量监测二期项目产品功能清单202604.xlsx` 是来源写法示例；目录中没有该文件时，不得引用其时效。

## P3 AI 评估

仅当 P1、P2 都无法给出该行时效时进入。必须：

- 功能匹配结果 = `未匹配`（若功能已 P1 命中、只是时效空，结果仍用已匹配/部分匹配，来源按 P1 降级第 2 步）
- 匹配模块 = `-`
- 匹配依据 = `未从标准产品功能清单和历史项目库中找到匹配项`
- 匹配来源 = `AI评估`
- 时效按 `ai-estimation.md` 拆原子任务累加，并在对话「假设与缺口」列出拆解

## 部分匹配如何加总

部分匹配 = 可复用底座时效 + 缺口时效。两段都要能追溯：

- 底座：P1 固定时效或 P2 中位数/组合
- 缺口：P2 相似改造项或 P3 原子任务
- 两段相加，**禁止** ×1.2、×改造系数、按人天经验加成

依据句式必须同时出现「已有」和「未覆盖/需新增」。

## 依赖模块

标准清单一行的依赖写在：

- `二级功能依赖模块`
- `三级功能依赖模块`

忽略：空、`-`、`无`、`无（核心基础模块）`。多个依赖按顿号或逗号拆开，去重后各出一行。

依赖行：

- 三级功能 = `{依赖模块名}*`（无空格）
- 一级/二级沿用主功能，或改为该依赖模块在标准清单中的真实层级（能查到则用真实层级）
- 功能匹配结果、来源按该依赖自己的 P1/P2/P3 结果写
- 主功能与依赖都计入合计

同一依赖被多个主功能引用时，**每个主功能下各出一行**（按规则「绑定即计入」），不要在表内自行去重省略；在摘要里提示「依赖模块重复出现，人工审核是否合并」。
