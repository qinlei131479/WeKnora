# 数据源登记与字段契约

本页定义如何登记本次任务可用的权威数据。技能不预设文件名、Sheet 名、业务领域或项目名。

数据源只允许来自：

1. 当前 request manifest 中的用户上传文件。
2. 知识库检索后下载到沙盒的文件。
3. 用户明确确认的对话内表格。

知识库检索结果必须记录知识库名和真实文件名；没有登记过的文件不能引用。

历史 request、历史会话的 uploads/outputs 不是本次数据源；除非当前 manifest 重新登记，否则禁止引用。

## 1. 文件性质

| 性质 | 作用 | 是否可提供时效 |
| --- | --- | --- |
| 标准清单 | 判断标准能力是否可复用 | 是；按命中行三列时效直读，三项都没有时为 0 |
| 历史工时清单 | 提供可比历史行时效 | 是，且必须可定位到行 |
| 需求清单 | 提供本次待评估能力 | 否 |
| 参考文档 | 解释业务背景或术语 | 否 |

一个文件可能包含多个 Sheet，性质按 Sheet 判断；不要把整个文件默认当成同一类数据源。

## 2. 每任务登记表

每个任务先生成一张数据源登记表。没有登记表，不进入匹配。

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 源ID | 是 | 如 `S1`、`H1`、`R1` |
| 文件名 | 是 | 真实文件名，不改写 |
| 知识库名 | 有则必填 | 从知识库获取时记录 |
| Sheet | 是 | 实际参与匹配的 Sheet |
| 文件性质 | 是 | 标准清单 / 历史工时清单 / 需求清单 / 参考文档 |
| 文件 hash | 有则必填 | 用于固定版本 |
| 表头行 | 是 | 实际表头所在行号 |
| 有效行范围 | 是 | 数据起止行，排除空行、说明行、合计行 |
| 字段映射 | 是 | 源表表头到标准字段的对应关系 |
| 可信度 | 是 | 已确认 / 待确认 |
| 用途限制 | 是 | 可作能力依据 / 可作时效依据 / 仅参考 |

历史工时清单必须由用户确认或由清单性质明确可知；否则只能作参考，不能作 P2 时效。

## 3. 标准清单字段契约

标准清单应映射到以下字段。源表表头不同但含义相同时，按同义字段处理。

| 标准字段 | 必要性 | 说明 |
| --- | --- | --- |
| 一级功能 | 是 | 标准产品或系统级模块 |
| 二级功能 | 是 | 子模块 |
| 二级功能是否为最小销售单元 | 是 | 值为「是」才可独立报价 |
| 二级功能依赖模块 | 有则必填 | `-`、`无`、空不展开 |
| 三级功能 | 有则必填 | 可复用功能点 |
| 三级功能是否为最小销售单元 | 有则必填 | 同义表头按含义映射 |
| 三级功能依赖模块 | 有则必填 | 多值按顿号或逗号拆分 |
| 核心功能描述 | 是 | 判断能力覆盖的主要依据 |
| 标准产品时效 | 有则登记 | P1 已匹配行直读；三项都没有时按规则 0 |
| 标准研发时效 | 有则登记 | P1 已匹配行直读；三项都没有时按规则 0 |
| 标准交付时效 | 有则登记 | P1 已匹配行直读；三项都没有时按规则 0 |

合并单元格必须按实际业务层级向下补齐后再判断。

## 4. 历史工时清单字段契约

历史工时清单应映射到以下字段：

| 标准字段 | 必要性 | 说明 |
| --- | --- | --- |
| 一级功能 | 建议 | 项目内模块 |
| 二级功能 | 建议 | 子模块 |
| 三级功能 / 功能点 | 是 | 历史可比项名称 |
| 功能描述 | 是 | 判断可比性的主要依据 |
| 产品时效 | 是 | 数值 |
| 研发时效 | 是 | 数值 |
| 交付时效 | 是 | 数值 |
| 合计 | 有则必填 | 仅作核对；不用于反拆 |

历史清单中的合计行、汇总行、备注行必须排除。

## 5. 需求清单字段契约

需求清单应映射到以下字段：

| 标准字段 | 必要性 | 说明 |
| --- | --- | --- |
| 一级功能 | 是 | 本次需求模块 |
| 二级功能 | 是 | 本次需求子模块 |
| 三级功能 | 建议 | 本次最小交付单元 |
| 核心功能描述 | 是 | 角色、动作、对象、目标 |
| 必做 / 非必做 | 有则必填 | 未标记时先澄清或写假设 |
| 已有 / 缺失 / 待确认 | 有则必填 | 人工标注必须转成显式字段 |

红色字体、黄色底色、批注、删除线不是可靠业务字段。只有用户说明其含义并转成显式状态后，才能参与匹配和估时。

## 6. 读取与校验

读取表格时执行：

1. 按 Sheet 实际数据读取，不按记忆或文件名推断。
2. 校验表头是否存在，字段映射是否完整。
3. 校验有效行范围内是否有空行、说明行、合计行。
4. 校验时效列是否为数值；空值保持为空，不能补默认值。标准行三项时效都为空时，按“仅标准且三项缺失”规则记 0。
5. 校验最小销售单元标记是否为已知值。
6. 保留每个源证据的 Sheet 和行号。

发现以下情况时，先澄清或降级，不能继续输出正式报价：

- 文件性质不明。
- 历史清单是否可作时效依据不明。
- 必要字段缺失且无同义字段。
- 表格维度元数据与实际行数不一致。
- 功能描述、最小销售单元或时效列无法对应。

标准清单没有产品、研发、交付三列，或命中行三项都为空时，不是阻塞项；该已匹配行三列按 0。部分缺失时，缺失列不能从其他列推测。

历史清单某行的产品、研发或交付时效缺失时，对应报价列不能从其他列推测；按 P3 原子任务拆解给值，不得填 `--`。

## 7. 证据引用格式

内部证据必须完整：

```text
源ID + 文件名 + Sheet + 行号 + 原始描述 + 参与字段值
```

可见来源至少写：

```text
{文件名}（Sheet：{Sheet}，行：{行号}）
```

多个源行用顿号或分号列出。来源来自知识库时，前缀知识库名：

```text
知识库 {知识库名} / {文件名}（Sheet：{Sheet}，行：{行号}）
```
