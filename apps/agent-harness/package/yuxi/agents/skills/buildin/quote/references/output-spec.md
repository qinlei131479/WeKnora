# 报价单输出规范

模板结构固化在本文件与 `../scripts/fill_quote.py`。本阶段只输出工时，不输出单价、税率或金额。本文中的占位符不代表真实文件；运行时必须替换为本次登记的数据源。

用 `../scripts/fill_quote.py --input <rows.json> --output <交付文件.xlsx>` 生成。改列定义时必须同步改脚本。

## 列定义（12 列，禁止增删改序）

| 列 | 字段 | 必填 | 规则 |
| --- | --- | --- | --- |
| A | 一级功能 | 是 | 每行都写，不留合并空白 |
| B | 二级功能 | 是 | 每行都写 |
| C | 三级功能 | 是 | 依赖模块在名称后加 `*`，无空格 |
| D | 核心功能描述 | 是 | 1–2 句，角色+动作+目标；自动换行 |
| E | 产品时效 | 是 | 人天，数字 |
| F | 研发时效 | 是 | 人天，数字 |
| G | 交付时效 | 是 | 人天，数字 |
| H | 时效总计 | 是 | 公式 `=E{n}+F{n}+G{n}` |
| I | 功能匹配结果 | 是 | 仅三值：`已匹配` / `部分匹配` / `未匹配` |
| J | 匹配模块/功能 | 是 | 已匹配、部分匹配写复用单元；未匹配填 `-` |
| K | 匹配依据说明 | 是 | 已匹配、部分匹配写理由；未匹配用固定句 |
| L | 匹配来源 | 是 | 能力来源和时效来源；未匹配填 `AI评估（原子任务拆解）` |

「功能匹配结果」用模板用词 **未匹配**，不用规则原文的「不匹配」。

## 版式

- 表头加粗，底边框，垂直居中；D/J/K/L 自动换行
- 数据行垂直居中，底边框；行高按描述长度取 44 / 58 / 72
- 合计行：合并 `A{last}:D{last}`，A 写 `合计`，E–H 为 `=SUM(...)`，I–L 空
- 列宽对齐脚本：A14.4 / B16.1 / C14.6 / D48 / E14.4 / F12 / G16.4 / H12 / I15.2 / J15.8 / K33.4 / L26.1

## 匹配模块写法

`{标准或历史的一级功能} > {被复用的最小销售单元或三级功能}`

不要写成「二级 > 三级」，不要只写三级名，也不要用系统名、平台名或架构名兜底。

## 匹配来源写法

`匹配来源` 必须写「能力来源」和「时效来源」。来源来自知识库时，加知识库名；来自本地文件时，写真实文件名。

单行来源格式：

```text
{实际文件名}（Sheet：{实际Sheet}，行：{实际行号}）
知识库 {知识库名} / {实际文件名}（Sheet：{实际Sheet}，行：{实际行号}）
```

| 情形 | 匹配来源 |
| --- | --- |
| 仅标准清单 | `{实际标准文件名}（Sheet：{实际Sheet}，行：{行号}）` |
| 仅历史清单 | `{实际历史文件名}（Sheet：{实际Sheet}，行：{行号}）` |
| 标准能力 + 历史时效 | `{标准来源} + {历史来源}` |
| 标准 + 历史组合能力 | `{标准来源1、标准来源2} + {历史来源}` |
| P3 | `AI评估（原子任务拆解）` |
| 功能命中但标准时效为空 | `{标准来源}；时效：AI评估（标准清单时效字段为空）` |

多行用顿号或分号列出；多段来源用 ` + ` 连接。禁止只写文件名，也禁止省略 Sheet 或行号。

## 依据句式（必须套用）

**已匹配：** `标准系统中{功能}已支持{能力}，可直接复用{界面/数据模型/流程}`

**部分匹配：** `标准/历史{功能}支持{已有能力}，但未覆盖{缺口}，需{改造动作}`

**未匹配（固定原文，不要改写）：** `未从标准产品功能清单和历史项目库中找到匹配项`

## 模拟金样（只学粒度与语气，不照抄业务内容）

以下业务名和数据都是演练占位。真实输出必须使用本次登记的功能名、源文件、Sheet 和行号。

### 金样 1 — 已匹配

| 字段 | 值 |
| --- | --- |
| 一级 / 二级 / 三级 | 示例业务模块 / 示例资料管理 / 示例资料维护 |
| 核心功能描述 | 管理员可新增、修改、删除和查询资料，统一维护名称、说明和状态 |
| 产品 / 研发 / 交付 / 总计 | 0.5 / 1 / 0.5 / 2 |
| 功能匹配结果 | 已匹配 |
| 匹配模块/功能 | 标准一级功能A > 资料维护 |
| 匹配依据说明 | 标准系统中资料维护已支持增删改查，可直接复用管理界面及底层数据模型 |
| 匹配来源 | {实际标准文件名}（Sheet：{实际Sheet}，行：{行号}） |

匹配模块使用 `一级 > 三级` 格式。依据中的能力必须能在引用行原文中逐项找到。

### 金样 2 — 部分匹配 + 依赖标记

| 字段 | 值 |
| --- | --- |
| 一级 / 二级 / 三级 | 示例业务模块 / 示例运行能力 / 外部平台对接* |
| 核心功能描述 | 支持按对象和周期配置任务，并对接多个外部平台完成处理 |
| 产品 / 研发 / 交付 / 总计 | 2 / 8 / 3 / 13 |
| 功能匹配结果 | 部分匹配 |
| 匹配模块/功能 | 标准一级功能B > 任务配置 |
| 匹配依据说明 | 标准系统支持配置任务对象和执行方式，但未覆盖多外部平台对接，需新增接口适配层 |
| 匹配来源 | {实际标准来源} + {实际历史来源} |

要点：三级名带 `*`；依据同时写已有能力和缺口；来源分别写能力来源和时效来源；时效明显高于金样 1。

### 金样 3 — 部分匹配（历史底座 + 场景改造）

| 字段 | 值 |
| --- | --- |
| 一级 / 二级 / 三级 | 示例对话能力 / 示例对话能力 / 推荐内容生成 |
| 核心功能描述 | 支持根据用户输入自动生成推荐内容条目 |
| 产品 / 研发 / 交付 / 总计 | 3 / 10 / 3 / 16 |
| 功能匹配结果 | 部分匹配 |
| 匹配模块/功能 | 标准一级功能C > 文本问答 |
| 匹配依据说明 | 历史文本问答支持交互和问题理解，可作为技术底座复用；但未覆盖自动生成推荐内容的业务逻辑，需改造处理规则 |
| 匹配来源 | {实际历史文件名}（Sheet：{实际Sheet}，行：{行号}） |

要点：承认可复用底座，同时写清场景差异和必须改造的业务逻辑。

### 金样 4 — 合计

| 字段 | 值 |
| --- | --- |
| A:D | 合并，文案 `合计` |
| 产品 / 研发 / 交付 / 总计 | 5.5 / 19 / 6.5 / 31 |

验算：`0.5+2+3=5.5`，`1+8+10=19`，`0.5+3+3=6.5`，`2+13+16=31`，且 `5.5+19+6.5=31`。交付文件用 SUM 公式，数字必须与此勾稽方式一致。

### 金样 5 — 未匹配字段范例（不是业务行）

| 功能匹配结果 | 匹配模块/功能 | 匹配依据说明 | 匹配来源 |
| --- | --- | --- | --- |
| 未匹配 | - | 未从标准产品功能清单和历史项目库中找到匹配项 | AI评估（原子任务拆解） |

真实未匹配业务行仍要填 A–H（含 P3 时效），I–L 用上表四字段。

## 时效量级对照（写行时自检）

| 类型 | 产品 | 研发 | 交付 | 总计 | 参照 |
| --- | --- | --- | --- | --- | --- |
| 标准 CRUD 直接复用 | 0.5 | 1 | 0.5 | 2 | 金样 1 |
| 有底座、需新增适配层 | 2 | 8 | 3 | 13 | 金样 2 |
| 有底座、需改业务逻辑 | 3 | 10 | 3 | 16 | 金样 3 |
| 历史原子任务（细粒度） | 0–0.5 | 0.5–2 | 0.2–0.5 | 0.2–2.7 | 已登记历史单行 |

报价行粒度接近金样 1–3 时，不要把历史单行人天直接填成整模块。细清单按历史粒度逐行报价时，才用细粒度量级；能取到真实源行时以真实源行为准。

## 评估台账

生成 Excel 前保留一张内部台账，每条业务行记录：

```json
{
  "row_id": "R001",
  "capability_evidence": ["源ID", "命中原文", "覆盖/缺口判断"],
  "effort_evidence": ["源ID", "取数方式", "计算式"],
  "status": "待核验"
}
```

台账不必写进交付 Excel，但必须在交付前完成核验；用户追问任一行时，要能用台账还原结论。

## JSON 输入约定

```json
{
  "rows": [
    {
      "l1": "示例业务模块",
      "l2": "示例资料管理",
      "l3": "示例资料维护",
      "desc": "管理员可新增、修改、删除和查询资料，统一维护名称、说明和状态",
      "product": 0.5,
      "dev": 1,
      "delivery": 0.5,
      "match_result": "已匹配",
      "match_module": "标准一级功能A > 资料维护",
      "match_reason": "标准系统中资料维护已支持增删改查，可直接复用管理界面及底层数据模型",
      "match_source": "{实际标准文件名}（Sheet：{实际Sheet}，行：{行号}）"
    }
  ]
}
```

`match_result` 只能是 `已匹配`、`部分匹配`、`未匹配`。
