# 报价单输出规范

模板结构固化在本文件与 `../scripts/fill_quote.py`。本阶段只输出工时，不输出单价、税率或金额。本文中的占位符不代表真实文件；运行时必须替换为本次登记的数据源。

用 `../scripts/fill_quote.py fill --input <rows.json> --output <交付文件.xlsx>` 生成；生成后必须用同一脚本的 `verify` 子命令勾稽（纯 Python，不需要 LibreOffice）：

```bash
python ../scripts/fill_quote.py fill   --input <rows.json> --output <交付文件.xlsx>
python ../scripts/fill_quote.py verify --file <交付文件.xlsx> --rows <rows.json>
```

改列定义时必须同步改脚本。

最终 Excel 必须放在 outputs 下，并用 `present_artifacts` 展示。

## 列定义（13 列，禁止增删改序）

| 列 | 字段 | 必填 | 规则 |
| --- | --- | --- | --- |
| A | 一级功能 | 是 | JSON 每行都写；同一个 `merge_group` 的相邻拆分行在 Excel 中合并 |
| B | 二级功能 | 是 | JSON 每行都写；同一个 `merge_group` 的相邻拆分行在 Excel 中合并 |
| C | 三级功能 | 是 | 依赖模块在名称后加 `*`，无空格 |
| D | 核心功能描述 | 是 | 1–2 句，角色+动作+目标；自动换行 |
| E | 产品时效 | 是 | 人天数字，**不允许 `--`**；无源行时按 P3 拆解给值，确实无需投入填 `0` |
| F | 研发时效 | 是 | 人天数字，**不允许 `--`**；同上 |
| G | 交付时效 | 是 | 人天数字，**不允许 `--`**；同上 |
| H | 时效总计 | 是 | 公式 `=E{n}+F{n}+G{n}` |
| I | 工时说明 | 是 | 必须逐列写 `产品=数值：…；研发=数值：…；交付=数值：…` 取数式；禁止只写匹配结论或“见来源” |
| J | 功能匹配结果 | 是 | 仅两值：`已匹配` / `未匹配` |
| K | 匹配模块/功能 | 是 | 已匹配写复用单元；未匹配填 `-` |
| L | 匹配依据说明 | 是 | 已匹配写理由；未匹配用固定句 |
| M | 匹配来源 | 是 | 能力来源和时效来源；未匹配填 `AI评估（原子任务拆解）` |

「功能匹配结果」用模板用词 **未匹配**，不用规则原文的「不匹配」。

## 版式

- 表头加粗，底边框，垂直居中；D/I/J/K/L/M 自动换行
- 数据行垂直居中，底边框；行高按描述长度取 44 / 58 / 72
- `merge_group` 必须恰好对应相邻两行，且两行一级、二级功能一致；生成器合并这两行的 A、B 单元格
- 合计行：合并 `A{last}:D{last}`，A 写 `合计`；E/F/G/H 四列均为 `SUM`，I–M 空
- 生成时写入打开即重算属性，交付前用 `verify` 勾稽，不需要 LibreOffice 预写缓存值
- 列宽对齐脚本：A14.4 / B16.1 / C14.6 / D48 / E14.4 / F12 / G16.4 / H12 / I48 / J15.2 / K15.8 / L33.4 / M26.1

## 匹配模块写法

`{标准或历史的一级功能} > {被复用的最小销售单元或三级功能}`

不要写成「二级 > 三级」，不要只写三级名，也不要用系统名、平台名或架构名兜底。

## 匹配来源写法

`匹配来源` 必须写「能力来源」和「时效来源」。来源来自知识库时，加知识库名；来自本地文件时，写真实文件名。

单行来源格式：

```text
{实际文件名}（Sheet：{实际Sheet}，行：{实际行号}）
知识库 {知识库名} / {实际文件名}（Sheet：{实际Sheet}，行：{实际行号}）
```

| 情形 | 匹配来源 |
| --- | --- |
| 仅标准清单且三项都有 | `{实际标准文件名}（Sheet：{实际Sheet}，行：{行号}）；时效：直读标准行` |
| 仅标准清单且三项都无 | `{实际标准文件名}（Sheet：{实际Sheet}，行：{行号}）；时效：三项缺失，按规则 0 人天` |
| 仅历史清单 | `{实际历史文件名}（Sheet：{实际Sheet}，行：{行号}）` |
| 标准时效 + 历史时效组合能力 | `{标准来源} + {历史来源}` |
| 标准行部分缺失 | `{标准来源}；时效：{产品/研发/交付}缺失，按 P3 原子任务补齐` |
| P3 | `AI评估（原子任务拆解）` |
| 拆分后的未匹配缺口 | `AI评估（原子任务拆解）` |

多行用顿号或分号列出；多段来源用 ` + ` 连接。禁止只写文件名，也禁止省略 Sheet 或行号。

## 工时说明写法

`工时说明` 是逐列取数台账，必须让读者不打开源表也能复算。固定骨架：

```text
产品={数值}：{取数式}；研发={数值}：{取数式}；交付={数值}：{取数式}
```

取数式由一项或多项组成，每项固定为：

```text
「{标准功能名 / 历史功能名 / AI原子任务名}」{数值}（{真实文件名}，Sheet：{Sheet}，行：{行号}）
「{AI原子任务名}」{数值}（AI评估，{L1-L4或T0-T3}，{为什么需要该任务}）
```

某列填 `0` 时，取数式写清为什么是 0，例如 `产品=0：无需产品设计，复用标准原型（{标准文件名}，Sheet：{Sheet}，行：{行号}）`。

多项用 ` + ` 连接，括号内最后列出的各数值之和必须等于该列工时。示例：

```text
产品=0.5：标准功能「直播播放监测」0.5（标准功能清单.xlsx，Sheet：标准能力，行：18；直读标准行）；研发=9：历史功能「直播监测」5（历史工时.xlsx，Sheet：项目工时，行：10） + 历史功能「点播监测」4（历史工时.xlsx，Sheet：项目工时，行：11）；交付=1.5：标准功能「直播播放监测」1.5（标准功能清单.xlsx，Sheet：标准能力，行：18；直读标准行）
```

| 场景 | 必写内容 |
| --- | --- |
| 标准行三项都有 | 每列写标准功能名、直读值、文件、Sheet 和行号 |
| 标准行三项都无 | 每列写 0，并保留命中的标准功能名、文件、Sheet、行号和“三项缺失，按规则0” |
| 标准行部分缺失 | 有值列直读；缺失列按 P3 原子任务拆解给值，并写明缺失后如何补齐 |
| 单条历史命中 | 每列写该历史功能名、直读值、文件、Sheet 和行号 |
| 多条历史命中 | 每列分别列出参与功能、各自数值和源行，再写出合计 |
| 部分覆盖拆分行 | 已匹配行只写标准/历史源行取数式；未匹配行只写 P3 原子任务取数式 |
| 未匹配 | 每列列出 AI 原子任务、数值、定级和原因 |
| 该角色无需投入 | 该列数值为 `0`，取数式写明为什么无需投入；不得写“无法评估” |

禁止把历史行改成“更合理”的数字；禁止把多条历史行改成平均值；禁止用泛化理由替代取数式；禁止在取数式外夹带不能求和的数字。`P2：功能目标一致，但方法论需新增` 只是匹配结论，不是工时说明。

## 依据句式（必须套用）

**已匹配：** `标准系统中{功能}已支持{能力}，可直接复用{界面/数据模型/流程}`

**部分覆盖已匹配行：** `标准/历史{功能}已支持{已有能力}，可直接复用{界面/数据模型/流程}`

**未匹配（句式固定，只允许在中间插入缺口能力）：**

```text
未从标准产品功能清单和历史项目库中找到{缺口能力}匹配项
```

- 完全未匹配：`{缺口能力}` 留空，即 `未从标准产品功能清单和历史项目库中找到匹配项`
- 部分覆盖的未匹配行：把缺口能力写进中间，例如 `未从标准产品功能清单和历史项目库中找到外部平台对接匹配项`
- 必须以「未从标准产品功能清单和历史项目库中找到」开头、以「匹配项」结尾；不要改写句式

## 评估台账

生成 Excel 前保留一张内部台账，每条业务行记录：

```json
{
  "row_id": "R001",
  "capability_evidence": ["源ID", "命中原文", "覆盖/缺口判断"],
  "effort_evidence": ["源ID", "逐列取数式", "每个参与项数值", "工时说明"],
  "status": "待核验"
}
```

台账不必写进交付 Excel，但必须在交付前完成核验；用户追问任一行时，要能用台账还原结论。

## JSON 输入约定

```json
{
  "rows": [
    {
      "l1": "示例业务模块",
      "l2": "示例资料管理",
      "l3": "示例资料维护",
      "desc": "管理员可新增、修改、删除和查询资料，统一维护名称、说明和状态",
      "product": 0,
      "dev": 0,
      "delivery": 0,
      "effort_reason": "产品=0：标准功能「资料维护」0（{实际标准文件名}，Sheet：{实际Sheet}，行：{行号}；三项缺失，按规则0）；研发=0：标准功能「资料维护」0（{实际标准文件名}，Sheet：{实际Sheet}，行：{行号}；三项缺失，按规则0）；交付=0：标准功能「资料维护」0（{实际标准文件名}，Sheet：{实际Sheet}，行：{行号}；三项缺失，按规则0）",
      "match_result": "已匹配",
      "match_module": "标准一级功能A > 资料维护",
      "match_reason": "标准系统中资料维护已支持增删改查，可直接复用管理界面及底层数据模型",
      "match_source": "{实际标准文件名}（Sheet：{实际Sheet}，行：{行号}）；时效：三项缺失，按规则 0 人天"
    }
  ]
}
```

`match_result` 只能是 `已匹配`、`未匹配`。

部分覆盖拆分时，相邻两行加同一个可选字段：

```json
{
  "merge_group": "SPLIT-001"
}
```
