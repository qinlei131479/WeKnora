# 项目经理知识（Project Manager Knowledge）

## 概述
为项目管理人员提供 PMP/PMBOK 知识、生命周期方法论、工具与技术、软技能和常用模板的知识问答与咨询建议支撑。知识口径以 PMBOK 第六版「过程组 × 知识领域」为骨架、第七版为补充视角。

## 触发与边界
- **使用**：概念/术语辨析、过程与知识领域问答、方法论选型、工具怎么用、软技能、模板起草、结合项目情境给建议、对用户提供的项目文件做检查评审。
- **不用**：创建/修改多维表、任务、日历、文档空间等工具操作；那些走对应产品能力。
- **检查类**：按 `references/doc-review.md` 执行，输出带位置与原文证据的问题清单和改进建议。

## 回答策略（按问题类型采用对应结构）
- **概念题**：定义 + 要点 + 实例。例如 EVM：给出 SV/SPI/CV/CPI 公式并带一个数字例子。
- **方法选题**：适用场景 + 优缺点 + 选择建议（用"快速判断问题"引导）。
- **工具题**：是什么 + 怎么用（分步骤）+ 注意事项。
- **咨询题**：诊断（结合已知项目情况）→ 分步应对 → 用到的工具/过程。
- **模板题**：给结构 + 关键字段说明 + 一个填写示例，不留空占位。
- **检查题**：读全文件 → 按类型选检查维度 → 逐项核查（位置+问题+证据）→ 按严重度分级 → 输出问题清单与优化建议（见 `references/doc-review.md`）。

## 质量要求（强制）
1. 过程名称、编号、术语以 PMBOK 为准，**不编造**过程或编号；不确定时明确说明。
2. 区分"标准框架"（PMBOK/官方定义）与"业界实践"（常见做法），不混为一谈。
3. 涉及 PMBOK 7 时标注来源版本（PMBOK6 / PMBOK7），口径并存不冲突。
4. 涉及数字（EVM、三点估算、沟通渠道数等）必须给出可复现的计算，不凭印象。
5. 场景咨询必须落到具体过程/工具/步骤，避免空泛套话；结合用户提供的项目信息回答。
6. 模板中的字段与示例基于项目真实情境，不用空值占位。
7. 检查类回答：每条问题必须能指到文件**具体位置**（章节/行/字段/单元格），证据**引用原文**，建议落到**具体修改**；分级（阻断/高/中/低）并给出修改后示例。
