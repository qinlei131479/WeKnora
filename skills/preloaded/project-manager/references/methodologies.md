# 生命周期方法论

按"需求明确度、变更频率、交付粒度"选择生命周期。没有"最好"的方法论，只有"更适合当前项目"的方法论。

## 一、主流方法论

### 预测型（瀑布 Waterfall）
- **特点**：阶段顺序执行（需求→设计→开发→测试→部署），前期大量规划，变更成本高。
- **适用**：需求明确稳定、交付物清晰、合规要求严格（如基建、大型制造）。
- **优点**：流程清晰、文档完整、易管控。**缺点**：变更慢、反馈晚。

### 迭代型（Iterative）
- **特点**：重复循环开发，每轮改进完整功能子集（如原型法、螺旋模型）。
- **适用**：需求部分明确、需要逐步验证。

### 增量型（Incremental）
- **特点**：分块交付可用的功能片段，每个增量可用。
- **适用**：可以按模块分批上线。

### 敏捷型（Agile）
- **特点**：短迭代（Sprint）、持续反馈、拥抱变更、自组织团队。常见框架：
  - **Scrum**：固定 Sprint、角色（PO/Scrum Master/团队）、仪式（计划/每日站会/评审/回顾）。
  - **Kanban**：看板拉式流动、在制品上限（WIP Limit）、持续交付。
  - **XP（极限编程）**：结对编程、TDD、持续集成。
- **适用**：需求变化快、创新探索型（软件/互联网产品）。
- **优点**：响应快、用户参与度高。**缺点**：范围不固定、对团队要求高。

### 混合型（Hybrid）
- **特点**：预测与敏捷组合，如"规划用瀑布、开发用敏捷"，或"按模块混合"。
- **适用**：组织转型期、项目不同部分成熟度不同。

### DevOps
- **特点**：开发与运维一体化，CI/CD 持续交付，强调自动化与文化。
- **适用**：软件持续部署场景，常与敏捷/混合配合。

## 二、选型决策框架

| 项目特征 | 倾向 |
|---|---|
| 需求明确、变更少 | 预测型（瀑布） |
| 需求模糊、探索性强 | 敏捷型 |
| 分阶段可控交付 | 增量/迭代型 |
| 组织成熟度不足、需过渡 | 混合型 |
| 需要快速持续上线 | DevOps + 敏捷 |

**快速判断问题**：① 需求能在项目开始前写清吗？② 客户能接受分期交付吗？③ 变更会被容忍吗？④ 合规/验收是否要求完整文档？回答越偏向"否/否/是/是"，越适合敏捷。

## 三、敏捷核心原则（参考敏捷宣言）

- 个体和互动高于流程和工具；可工作的软件高于详尽的文档；客户合作高于合同谈判；响应变化高于遵循计划。
- 常用实践：用户故事、Sprint 评审、每日站会、回顾会议、看板、TDD。
